当前代码在 main，2026-10-09整合材料已完成。技术题原代码和持仓已复现，12个新候选没有达到替换标准。本任务优先补作品证据，不改技术题持仓，不假设Kimi已经接入产品API。

## 你实际要发给 Kimi 的东西

先解压 `Claim2Value_Kimi任务包_20261009.zip`。网页版先上传 `01_发给Kimi的提示词.md` 和 `originals/` 下三份PDF；再上传 `02_kimi_return_template.json` 和 `reference/` 下的来源清单、四条Claim快照。文件数量受限时先传提示词与三份PDF。代码客户端可以直接读取解压目录，先阅读提示词。ZIP能否被直接展开取决于所用客户端，不把支持ZIP设成前置条件。

四张 `page_previews/` 是同一原PDF的原页预览，不是新来源。若PDF表格抽取错位，结合这些图片逐列核对；打印页和PDF文件页分别记录。其他附件只给历史背景，不直接复制为本轮已认证结论。

## Kimi输出与人工操作

先要求一张四条状态表，再填写JSON模板，每条一条主要来源；一条声明有多份材料时在补充清单说明。状态只有 `not_started`、`candidate_link`、`read_original`、`not_found`、`conflict`。中文表格可对应未开始、仅候选链接、已读原文、未找到、口径冲突。未找到须说明实际检索范围；没有联网工具只报告上传文件中的结果。

`read_original`只表示Kimi声称读了原文，仍须人工核对。网页版不能下载或计算SHA-256时这些字段留空，不编造。本人下载真正的原PDF到仓库外目录，并由有文件权限的一方计算哈希；只有网页原文、截图、付费蓝皮书或无法下载时先交已有线索，接入器不把它伪装为PDF。

人工最小验收：打开本轮关键原页，确认公司、型号、表头、列、数值、单位、日期、版本和限定词。未确认的提升比例、排行或工况不标最终supported。普通聊天回答与搜索摘要不是原件。模型自行复核不等于独立人工标签。

第一轮控制60—90分钟，先四条状态和一张可定位的官方原表；找不到则如实交检索记录。第二轮才从新原文选10—15条真实候选，使用另一个候选文件，不塞入本轮四条模板，也不预填标准答案。

## 回传给项目助手

交 `02_kimi_return_template.json` 的填好版本、取得的原PDF、`urgent_claim_status.md`、`download_status.md`。后两项写实际搜索范围、已读页面、下载失败、待本人处理的登录、版本冲突、工具和模型名称、实际耗时及实付API费用；网页订阅不能换算成虚构API费用。

原件放原有私有Drive材料目录。GitHub只放可公开的代码与必要索引；无需提交校园账号、API密钥或商业数据库导出。

在仓库中执行（Windows的python也可；路径按实际改）：

```bash
python scripts/prepare_kimi_evidence.py --input /path/kimi_return.json --source-root /path/evidence_inbox --out /path/intake_run_01
```

回执中的 `text_review_count` 大于0后才运行：

```bash
python scripts/review_evidence_batch.py --input /path/intake_run_01/evidence_batch.csv --out /path/rule_review_01
```

接入器核对四条ID、声明未被改写、路径边界、PDF文件头和原件SHA-256；它不解析PDF页数、不认证网址主体、不核对摘录真伪或表格列。现有核查器只检查所给文字，保留abstain，不更新Claim Bank，也不从新文字直接生成估值。人工确定原件、来源与可比性后，再单独审查状态修订。
