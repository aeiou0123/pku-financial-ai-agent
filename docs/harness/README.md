这一入口接受自己的文件和模型 API，分别执行财务／估值研究和量化处理／回测。Windows 双击工作区根目录的 `start_harness.bat`，打开 http://127.0.0.1:8510。原有 `start_demo.bat` 保留固定案例；冻结技术题没有改动。

需要 Python 3.12、约 500 MB 环境空间；首次安装联网，后续本地计算无需模型 API。首次使用打开侧栏“模型连接”，选择配置预设和协议，填写地址与 API Key 后按 Enter，点击“获取模型列表”，选择模型，再点击“测试连接”。列表接口不支持时，仍可手动填写服务商的模型 ID。支持 OpenAI Chat Completions 与 Anthropic Messages 文本接口，未验证所有服务商兼容性。也可使用 `C2V_API_BASE`、`C2V_MODEL`、`C2V_API_KEY` 环境变量。密钥不保存到运行目录；关闭浏览器会话或点击清除即可移除会话中的值。

直接使用的依赖版本固定在 `requirements-harness.txt`，间接依赖由 pip 解析。首次安装大小随已有缓存和间接版本变化。端口被占用时可设置 `C2V_PORT`，例如 8511。

## 测试模型连接

地址示例可在侧栏展开并复制。OpenAI 协议下，下面的输入都归一到 `https://api.openai.com/v1/chat/completions`：

```text
https://api.openai.com
https://api.openai.com/
https://api.openai.com/v1
https://api.openai.com/v1/
https://api.openai.com/v1/chat/completions
https://api.openai.com/v1/chat/completions/
https://api.openai.com/v1/completions
```

`/completions` 仅为地址输入兼容，不实现旧式 Completions 请求；服务仍须支持 Chat Completions。Anthropic 协议可填 `https://api.anthropic.com`、`https://api.anthropic.com/v1` 或 `https://api.anthropic.com/v1/messages`，末尾斜杠均可。只填域名时默认补 `/v1`；自定义服务路径保留，不猜其版本号。界面显示最终生成与模型列表地址，便于核对。Responses 地址和协议不匹配的完整地址会被拒绝。

“获取模型列表”只在点击时发送一次 GET，不要求先填写模型名称、不发送研究材料，也不调用文本生成。OpenAI 协议使用基础地址下 `/models` 与 Bearer 认证；Anthropic 协议使用 `/v1/models`、`x-api-key` 与版本头。列表去重，最多显示1000项；服务返回后续页时会标注未显示全部，不自动翻页或重试。列表仅保留在当前会话，改地址、协议或密钥后清除；选中模型同步到“模型名称”，仍可手动覆盖。404、权限错误、超时、空列表或格式错误不会替换手填模型，不会假造可用名称。列表可能包含音频或嵌入模型，须选支持文本协议的模型，再用“测试连接”核验。

列表接口依据：[OpenAI模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)、[Anthropic模型列表](https://platform.claude.com/docs/en/api/models/list)，2026-10-10读取。自定义服务和Kimi订阅是否提供该列表，以实际返回为准，列表成功不等于该模型可用于研究任务。

Kimi Code 订阅用户选择“Kimi Code 订阅”，程序填入 `https://api.kimi.com/coding/v1`、`kimi-for-coding` 和 OpenAI 协议。密钥从 Kimi Code 控制台取得，与 Moonshot 开放平台密钥分开。预设不改写已填密钥，也不自动发送请求。其他服务商按其文档设置；完整 `/chat/completions` 或 `/messages` 地址也可自动转为对应 Base URL。

“测试连接”只发送一条小请求，要求返回 OK，不发送上传文件或研究要求；输出上限 256 token、超时 30 秒，会使用少量额度。Kimi Code 测试关闭思考，研究任务沿用服务商默认思考设置。连接结果显示耗时、接口、模型 ID、用量和返回文本；HTTP 200 但没有文本会单独提示。修改地址、协议、模型或密钥会清除旧测试结果。

请求不强制设置 temperature 或 top_p，避免与服务商模型要求冲突。研究任务的输出上限默认 8,192 token，可在侧栏调整；截断、空文本和非法 JSON 均不会被当成有效研究结果。400 等错误显示脱敏后的“服务端说明”，以实际错误内容判断原因。客户端标识为真实的 `Claim2Value-Harness/0.2`。

展开“研究请求与分批设置”：研究请求超时默认240秒，可选30—600秒；默认失败后最多再试2次，可设0关闭；每次操作最多40次请求，重试也计入。网络中断、临时服务错误和无法解析的正文有限重试，认证、硬额度和预算问题停止。超时可能发生在服务端已经处理之后，再试可能重复耗用额度。连接测试仍为一次30秒的小请求，成功不保证长任务一定成功。

OpenAI研究请求默认尝试 `response_format: json_object`；服务明确返回不支持此参数时，在剩余重试次数和预算内撤去约束，沿用原有字段要求。也可手动选择“仅提示词约束”。允许唯一完整JSON外有代码块或说明文字；重复字段、多个对象、截断和只有思考过程的响应不采纳。引用、字段和日期的核验要求不变，程序不替模型补事实。

配置依据：[Kimi Code 官方文档](https://www.kimi.com/code/docs/)、[模型与思考设置](https://www.kimi.com/code/docs/kimi-code/models.html)、[错误说明](https://www.kimi.com/code/docs/en/kimi-code/error-reference.html)，核对日期 2026-10-10。当日负责人反馈此预设下“测试成功了”；这只确认实际连接测试，上传文件的模型提取质量仍需另行核验。

## 财务／估值研究

首页的“检查研究观点”进入“论点审查与兑现条件”：上传公告和年报，确认信息范围，让模型拆解条件并查找支持／反证。估值按需开启，核对参数后绑定到产能、投产、销量、价格和成本模型。可反推目标EV或经营NOPAT，并用声明的降价／延期范围检查约束。完整操作、计算口径和自研边界见[产业研究流程](industry_workflow.md)。引用匹配不证明语义正确；模型判断和未来参数均须确认。

下面的原有财务流程从“财务整理与盈利解释”进入：

1. 上传 PDF、DOCX、TXT、MD、CSV 或 XLSX，写明要核对的指标和期间，点击“读取文件”。先查看解析范围及缺页提示。
2. 点击“提取／继续财务候选”，已解析文字及要求分批发送给自己的模型服务商。模型输出先经过原文摘录、文件指纹和定位匹配。它们仍是候选：正确摘录不等于正确字段映射。临时失败批次留在缺口表，后面的批次继续；认证、硬额度和预算问题停止。再次点击只请求未缓存的部分。
3. 对照原件核对 16 列字段，填写实际披露日期、单位、报表类型及更正版本，勾选确认后校验。未取得的日期、定义和口径应保持缺失；不要为了通过检查填猜测值。只有部分批次完成时，另行确认已核对未完成范围，才能使用部分候选校验；成果会保留缺口，不标为全文审查。候选或覆盖范围变化会要求重新确认。
4. 也可以同时上传已整理的 16 列财务长表 CSV 与被引用的原件，直接执行校验。字段顺序见 `examples/synthetic_financial.csv`；原件名可使用原始文件名，程序转为本次安全存储名，哈希须与上传的字节一致。
5. 得到标准化 CSV、质量报告、历史比率、Excel 与研究记录。不同披露日期、修订和报表口径分别计算；缺失不等于零，中期不自动年化或差分。
6. 可另填五年企业自由现金流 FCFF（元）、折现率、永续增长率和可选净债务，计算 DCF 与敏感性。五年数值可用中文或英文逗号分隔，例如 `1000000，1100000，1200000，1300000，1400000`；这些只是填写示例，不会自动代入。金额内部不使用千位逗号。它们是用户假设，不从历史报表或模型意见自动升级为预测事实。净债务缺失时只输出企业价值，不给每股目标价。

校验通过后，可使用“解释盈利变化”：选择同公司、同披露日、同报表口径和同修订版本的一组连续两年年度数据，点击“生成盈利变化研究底稿”。需要两期收入与成本；利润总额、税费、合并净利润和归母净利润齐备时会生成归母盈利桥，否则只分解毛利并列出缺字段。输出列明收入、毛利率及其余会计项目的贡献和原件定位，并比较经营现金流；它不把会计变化当成技术因果贡献。该功能不额外调用模型。导出 XLSX、JSON 和 Markdown 纳入本次成果 ZIP。完整适用边界与真实算例见[产品审查与改造](product_revision_20261010.md)。

单文件上限 20 MB，每次 10 个、合计 60 MB。本机解析PDF最多1,000页，各文件文字最多1,000,000字符，达到本机上限会提示。解析上限与模型上下文上限分开：财务提取默认单批最多6,000原文字符，可选1,000—16,000，提示词与定位信息另占上下文。页面显示解析量、预计批数和实际完成范围。遇到上下文超限或输出截断，财务批次可继续拆小（最多四层）；仍失败的范围留为缺口。扫描 PDF 不含 OCR；DOCX 定位为段落，不含页眉页脚等附属内容。XLSX 读取工作表缓存值，公式必须先在 Excel 保存计算结果。全部批次完成也不证明每一项证据都已提取或判断正确。

## 量化处理与回测

上传 CSV／XLSX 日频长表，选择工作表和列映射：日期 `YYYY-MM-DD`、六位文本股票代码、已复权收盘价。每个交易日、每只股票一行，要求完整的日期×股票面板，最多 100 万行；本版不处理停牌、上市退出、稀疏行情或原始行情复权。

可直接设置参数，也可让模型根据列名及研究要求提出待确认计划。支持价格动量或已有因子排序；不执行模型生成的任意代码。已有因子还需要真实 `available_at`，包含时分和时区（如 `2025-01-02T14:30:00+08:00`），超过当日 15:00 的值不进入当日信号，缺失因子不能冒充零。

信号在 T 日收盘后形成，T+1 日收盘成交，T+2 日计入首笔持仓收益。每日等权再平衡，按价格漂移后的实际双向换手 × 单边 bps 计算费用，初始买入收费，不强制期末清仓。基准同日进入、等权再平衡并扣相同费用。允许碎股，未模拟涨跌停、冲击成本和成交量约束，不能把样本内结果写成比赛测试成绩或交易可实现收益。

输出清洗后的数据、每日毛／净收益、费用、净值、持仓信号与成交日期、Rank IC、收益与回撤指标。年化使用 252 个交易日、Sharpe 无风险利率取零。IC 使用下一成交后一期收益，仅作评价，不进入选股。可让模型依据本地结果写解读草稿；草稿仍需审阅。

回测后可预先声明1—12组参数并运行“策略诊断”：共同区间的毛／净收益、同费率基准、换手、年度分段及成本压力分别展示。所有尝试登记在本地，失败组保留，不自动选最好一组；已查看区间不叫未触碰留出集。详见[产业研究流程](industry_workflow.md)。

## 运行与恢复

运行保存在 `work/harness_runs/<运行编号>/`：`sources/` 为原件；`outputs/` 为结果；`run.json`、`events.jsonl` 记录状态和步骤。财务提取按批次缓存已完成结果；同一浏览器会话、同一文件及要求失败后可继续，改变模型、要求或分批范围会重新处理，改变等待时间或重试次数不会使相同已完成批次失效。`extraction_progress.json` 记录解析和批次覆盖，`request_diagnostics.json` 记录请求设置与尝试。论点审查失败后显示已完成条件并可下载，继续时复用完成条件。关闭会话后原件与结果保留，但当前版本不提供跨会话导入继续按钮。

论点审查的“文件来源登记”始终显示：披露日期是公告实际公开日，报告期间不能替代它。缺日期或超过信息截止日的材料不会进入审查，但不代表文件损坏。模型拟定计划失败时，可以点击“使用本地研究模板（不调用模型）”，按产品和研究要求编辑条件及检索词、确认后再审查。模板不是模型结论，也未阅读证据；没有API时只完成模板编辑与本地计算。

财务计算、DCF 和回测各保存独立快照，下载按钮对应当前显示的运行编号；旧运行保留在本机。成果 ZIP 包含输出、输入指纹、处理步骤和校验清单，排除上传原件与 API Key。输出中可能含数据库原值或原文摘录，分享前需由持有权限的人确认范围。

样例均为合成数据，仅用于操作和算法核验。自动化检查、本机浏览器操作、真实模型调用与真人试用分别记录，不能相互替代。本版没有实时检索、数据库登录、自动交易、任意 Python 执行或泛化的多轮工具发现。

常见问题：密钥或模型名称错误时检查服务商控制台及“服务端说明”，输入密钥后按Enter确认；工作台按源文件指纹刷新变动的本地计算模块，其他应用代码更新仍需重启后台；扫描件先自行 OCR；缺日期和字段定义请补原件；代码丢前导零请改为文本；面板不完整请选择真实共同覆盖区间，不要把缺价填成零。
