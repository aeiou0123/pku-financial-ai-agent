## 启动

Windows 安装 Python 3.12 与 Git 后，在一个新的测试目录运行：

```powershell
git clone --branch industry-research-harness-20261010 --single-branch https://github.com/aeiou0123/pku-financial-ai-agent.git Claim2Value-test
cd Claim2Value-test
```

双击根目录 `start_harness.bat`。首次启动联网安装依赖，之后打开 http://127.0.0.1:8510 。在侧栏“模型连接”选择协议、填写地址与自己的密钥，输入后按 Enter。展开“地址填写示例”可复制不同形式；核对下方实际请求地址。点击“获取模型列表”，从列表选一个支持文本协议的模型，再点“测试连接”；获取失败时可手动填写模型名称。不要提交或共享密钥。

## 走一次产业研究

1. 选择“财务／估值研究 → 论点审查与兑现条件”。同时上传仓库 `docs/harness/examples/` 内的 `synthetic_industry.txt` 与 `synthetic_industry_counterevidence.txt`。两份均为合成材料。
2. “研究要求”填写下面的文字；研究公司填“公司甲”，产品／业务范围填“减速器”，信息截止日选 `2026-10-10`。

```text
请审查公司甲“新增减速器产能能够支持未来两年收入与利润增长”的论点。
检查原有与新增产能、投产计划及延期风险、订单依据、售价和成本。
并列支持材料、反证与材料未覆盖的条件，逐条引用原文。
客户名单不能当成订单，计划产能不能当成已实现销量。
```

3. 分别填写文件来源：第一份披露日 `2026-01-01`，counterevidence 文件披露日 `2026-02-01`；来源类型均选“合成测试”，材料公司“公司甲”，材料产品“减速器”。每份分别勾选“已核对日期和适用范围”。
4. 点击“拟定研究计划”，检查是否包含产能、投产与延期、订单、售价和成本，勾选计划确认，再点“审查证据／继续”。按钮灰色时，按旁边列出的具体缺项处理。检查模型是否引用了延期、降价与订单缺口；模型具体返回不保证每次相同。

   如果长任务超时，在“模型连接 → 研究请求与分批设置”将研究请求超时调至300—600秒，自动重试保持最多2次；可设0关闭。重试也计入请求数，可能再耗用额度。“测试连接”成功只表示小请求通过。拟定计划失败时可选本地模板、编辑条件和检索词后确认。材料披露日期在“文件来源登记”中填写，不能用报告期间代替；耳机等产品研究也可以用本地模板起草。
5. 如有原有设计产能100000台/年的正确参数候选，可核对后确认、保存，并绑定到“原有年产能”和2027—2031年。未来沿用仍是情景假设。不要把计划投产日确认为已实现投产日。没有合格候选就保留缺口，用明确的默认假设体验计算。
6. 开启“继续做盈利与估值情景（可选）”。首次计算保持默认参数，包括新增产能0、销量情景倍数1、目标口径“不反推”；不勾选业务覆盖全公司。核对未来参数假设后点击“计算兑现条件”，查看条件价值、现金流与订单缺口，下载成果ZIP。
7. 把“销量情景倍数”改为2并按 Enter，再计算。2027年销量120000台超过100000台产能，应提示冲突、暂缓估值。这是合成假设下的约束检查，不是公司实际估值。

财务候选提取失败时，查看完成批数及缺口表；临时错误批次跳过后仍处理后续批次。下载可以保留已完成结果。继续按钮会复用相同文件、要求和模型下的成功批次。若要先使用部分候选，须确认未完成范围，再核对字段与原件；导出的报告明确标为部分覆盖。论点审查也会显示已完成条件，继续时复用。请保留错误说明、完成批数和运行编号，不要仅截图“小请求测试成功”。

## 测试反馈

记录代码版本（`git rev-parse HEAD`）、模型名称、是否走完、错误文字、难理解的步骤、遗漏的反证，以及两次计算结果。保留失败与中断，不仅记录成功。可共享有权限分享的成果ZIP，勿发送密钥或账户信息。

本入口用于真人试用；开发检查通过不等于真实模型研究质量已验证。完整计算边界见[产业研究流程](industry_workflow.md)，按钮修复与实际验证见[修复记录](review_gate_fix_20261010.md)。
